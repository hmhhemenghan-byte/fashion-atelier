# Phase 27 — Provenance Dossier / 成衣溯源档案

## 目标

把已经通过成衣验收的真实版本整理成可发布、可验证、可长期保存的作品档案。该阶段让材料、制作、护理与人工签核事实回到品牌前台，但不扩展为购买者登记、库存、订单、产品追踪平台或法规认证系统。

## 唯一入口

- 来源必须是 `status = accepted` 且拥有唯一 `NERA-ACCEPT` 标识的 `production_acceptances` 记录；
- 每个来源可以建立多个修订，但同一修订不可覆盖；
- 来源验收、生产放行与作品身份只读引用，不被档案写回；
- 私密验收图片永不进入公开档案 API 或页面。

## 数据结构

### `provenance_dossiers`

保存档案编号、公开 slug、来源验收、作品、修订、状态、人工决定、设计故事、材料披露、制作方与地点、完成日期、护理、修复、溯源说明、公开摘要以及复核、发布、退役事实。

状态按 `draft → in_review → published → retired` 推进；草稿或复核版本也可以作废。发布版本只允许退役，不能修改正文或核对结果。

### `provenance_dossier_checks`

每个修订自动建立六项关键检查：

1. 作品与实物身份；
2. NERA-GO 与 NERA-ACCEPT 签核来源；
3. 材料披露；
4. 制作方、地点与日期；
5. 护理与修复；
6. 公开文案与隐私边界。

所有关键检查必须为 `pass`；`na` 不替代关键事实。

## 人工发布门槛

发布要求同时满足：

- 来源仍保持有效的 `NERA-ACCEPT`；
- 人工决定明确为 `publish`；
- 标题、slug、设计故事、材料、制作方、制作地点、完成日期、护理、修复和公开摘要完整；
- 六项关键核对全部通过；
- 发布人和发布时间由服务端记录。

## 公开页面

`/provenance/[slug]` 只呈现 `published` 修订。页面使用作品公开主图，展示设计故事、材料、制作与护理事实，以及档案编号、`NERA-ACCEPT` 和上游 `NERA-GO`。页面明确说明这是 NÉRA ATELIER 自有档案，不替代第三方检测、法规认证或产品标签。

## 安全与边界

- Studio 读写接口继续要求管理员身份并拒绝跨源写入；
- 已发布、已退役和已作废记录被冻结；
- 不读取公开页访问者身份，不记录购买者或持有人；
- 不生成库存、订单、采购、财务或 ERP 数据；
- 不自动发布，不自动生成无法证明的可持续性或产地声明。
