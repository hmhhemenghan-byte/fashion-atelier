# Phase 13 — Sample Performance

Sample Performance 是 Sample Inventory 与 Sample Fulfilment 之上的只读分析层。它不建立另一套业务事实，也不会改写资产、借调或盘点记录。

## 数据范围

- 资产基数：`sample_assets` 中未归档、并符合部门、系列、类别和颜色筛选的实体资产。
- 送出记录：`sample_loan_items` 已绑定 `sample_asset_id`，且借调单或单件状态证明样衣已经发出。
- 发出时间：优先使用 `sample_loans.outbound_sent_at`；旧记录缺失该字段时，只有状态已进入发出后的阶段才使用借调单创建时间作为兼容基线。
- 归还时间：优先使用 `return_received_at`，旧的终态记录缺失该字段时使用借调项最后更新时间。
- 未绑定实体资产的预约、准备中借调和已取消借调不会计入效能。

## 核心指标

| 指标 | 计算方式 |
| --- | --- |
| 样衣使用率 | 周期内至少送出一次的资产数 ÷ 筛选后的实体资产数 |
| 平均送出次数 | 周期内全部实体送出次数 ÷ 筛选后的实体资产数 |
| 未送出资产 | 筛选资产中周期内送出次数为 0 的资产 |
| 平均归还天数 | 已完成归还记录的 `归还时间 − 发出时间` 平均值 |
| 按时归还率 | 有预计归还日期且完成归还的记录中，按期归还的比例 |
| 需求压力 | 同一 Look 的周期送出次数 ÷ 对应实体资产数量 |
| 逾期资产 | 尚未终结，且预计归还日期早于当前时间的实体借调项 |

所有比率均在服务端根据当前 D1 数据即时计算。筛选目的地或用途时，资产基数保持不变，但只有符合条件的送出记录进入分子，因此可回答“这批资产在某个市场或用途中的实际使用情况”。

## 界面与导出

- Studio 的 Phase 13 提供时间、部门、系列、类别、目的地、颜色和用途筛选。
- 送出节奏、单件排行、Look 压力、类别/部门/用途/目的地拆分和处置队列使用同一份报告结果。
- `/api/studio/sample-performance` 返回 JSON。
- 在同一路径追加 `format=csv` 会导出当前筛选范围内的资产级 UTF-8 CSV。
- API 继续受设计师身份和管理员白名单保护。

## 可移植性

效能报告没有新增数据库表或供应商专属分析格式。迁移时只需保留作品、样衣资产、借调单和借调项中的稳定 ID 与时间字段，`lib/sample-performance.ts` 即可在新的数据库适配器上重新计算全部指标。

本阶段只衡量可核验的运营使用，不推断媒体曝光、销售额或 Media Impact Value。第 14 阶段已通过独立的 Placement 与 Placement Item 关系表关联送出记录和具体 Look；外部指标继续保留来源与核验口径，不会写回实体资产事实。
